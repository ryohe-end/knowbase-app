# 引き継ぎ：スタンプ景品 / ホームバナー 入稿UI（knowbie store-settings）

member アプリ（iOS/Android）＋ member-app-server 側は実装済み。**knowbie 側は「データ層の雛形」まで用意済み**で、残りは **React UI（store-settings 配下の画面）** を別タスクで実装する。

- ✅ member-app-server: 共有DBのテーブル/カラム（マイグレーション）＋ 読み取りAPI（`GET /member/stamp-card` 拡張、`GET /member/banners`）
- ✅ member アプリ: 景品ラインナップ／促進／案内の表示、ホームバナーのカルーセル表示
- ✅ knowbie データ層（本引き継ぎで追加）: 型定義＋API route（共有Postgresへ read/write）
- ⬜ **knowbie UI（要実装）**: 景品設定画面 / バナー設定画面

---

## 1. 全体像・データ契約

保存先は **member と同一の PostgreSQL**（`lib/memberDb.ts` の `query()` が接続。`wf_member_app_prod`）。テーブル/カラムは member-app-server のマイグレーションで作成済み（**要 dev/prod 適用**）。

### 景品（店舗 = clubCode 単位）
- `club__c` 追加カラム（1:1 設定）
  - `stamp_card_support_flag__c boolean` … この店舗でスタンプカード機能ON/OFF
  - `stamp_card_month_label__c varchar(60)` … 例 "7月"
  - `stamp_card_promo_text__c text` … 促進文言（空ならアプリが景品から自動生成）
  - `stamp_card_announcement__c text` … ご案内事項
- `stamp_card_prize` テーブル（1:多。club_code 単位）
  - `club_code, required_count(int), name, image_url, description, display_order`
- member 参照: `GET /member/stamp-card` が、`stamp_card_support_flag__c=true` かつ最新の進行中カード時に `prizes / month_label / promo_text / announcement` を返す。

### バナー（ブランド = app_type 単位。**店舗別ではない**）
- `app_banner` テーブル
  - `app_type('joyfit'|'fit365'|'wf'), title, image_url, link_url, display_order, is_active, start_at, end_at`
- member 参照: `GET /member/banners` が JWT の `app_type` で、`is_active` かつ掲載期間内のバナーを `display_order` 順に返す。ホームの「お知らせの下」にカルーセル表示、タップで `link_url` 遷移。

### 画像（重要）
`image_url` は **S3 の絶対URL**。knowbie 既存の画像アップロードを使う:
1. `POST /api/store-settings/media/upload-image` → `{ ok, presignedUrl, publicUrl, key }`
2. クライアントが `presignedUrl` にファイルを PUT
3. `publicUrl` を `imageUrl` として保存（`basic/page.tsx:416` / `dm/page.tsx:340` が既存例）

## 2. 追加済みファイル（データ層の雛形）

| ファイル | 役割 |
|---|---|
| `types/stampCardSettings.ts` | 景品設定の型（`StampCardSettings` / `StampCardPrize`） |
| `types/bannerSettings.ts` | バナー設定の型（`BannerSettings` / `AppBanner` / `AppType`） |
| `app/api/store-settings/stamp-card/route.ts` | 景品設定 GET/POST（clubCode 単位、POSTはadmin） |
| `app/api/store-settings/banners/route.ts` | バナー設定 GET/POST（app_type 単位、POSTはadmin） |

いずれも `basic/route.ts` と同じ流儀（`kb_user` cookie→DynamoDBでrole/clubCodes、`query()` で共有Postgres、レスポンス `{ ok, ... }`、`runtime="nodejs"` / `dynamic="force-dynamic"`）。POST は `role === "admin"` のみ。景品は `clubCodes` スコープでも制限。バナーは店舗横断のため admin のみ。

## 3. API 契約（UIが叩く先）

### 景品
- `GET /api/store-settings/stamp-card?clubCode=XXXX` → `{ ok: true, settings: StampCardSettings }`
- `POST /api/store-settings/stamp-card`（body: `StampCardSettings`）→ `{ ok: true, settings }`
  - 保存は「club__c 更新」＋「stamp_card_prize を club 単位で丸ごと置換（CTEで原子的）」。
  - バリデーション: `requiredCount` 正の整数、`name` 必須、`imageUrl` 必須。

### バナー
- `GET /api/store-settings/banners?appType=joyfit|fit365|wf` → `{ ok: true, settings: BannerSettings }`
- `POST /api/store-settings/banners`（body: `BannerSettings`）→ `{ ok: true, settings }`
  - 保存は app_type 単位で `app_banner` を丸ごと置換。
  - バリデーション: `imageUrl` 必須。`isActive` 既定 true。`startAt/endAt` は ISO文字列 or null。

## 4. UI 実装ガイド（別タスク・要実装）

`app/store-settings/` 配下に画面を追加する。既存の作法を踏襲:

### 景品設定画面（店舗単位）
- 参考: `app/store-settings/basic/page.tsx`（`clubCode` は `useSearchParams()`、未指定時は `StoreSelector` で選択）。
- フォーム構成:
  - 機能ON/OFFトグル（`supportFlag`）
  - 対象月ラベル（`monthLabel`）/ 促進文言（`promoText`）/ ご案内事項（`announcement`）
  - 景品リスト（追加/削除/並べ替え）: 各行 `画像(アップロード)` `requiredCount` `name` `description`
  - 画像は `media/upload-image` で S3 → `publicUrl` を `imageUrl` に。
- 保存: `POST /api/store-settings/stamp-card`。`useToast` / `AdminLoadingOverlay` は既存踏襲。

### バナー設定画面（ブランド単位・admin）
- **店舗選択ではなく app_type 選択**（joyfit/fit365）にする。store-settings のサブ画面にするか、admin 配下にするかは要判断（バナーは店舗横断のため、店舗選択UIとは別導線が自然）。
- フォーム: バナーリスト（画像/リンク/タイトル/表示順/掲載ON/期間）。画像は同上。
- 保存: `POST /api/store-settings/banners`。

### メニュー導線
- `app/store-settings/page.tsx`（7項目のカード）に「スタンプカード景品」を追加。バナーは app_type 単位のため別導線を検討。

## 5. 前提・要判断（引き継ぎ時の確認事項）
1. **DBマイグレーション適用**: member-app-server の `stamp_card_prize` / `app_banner` / `club__c` 追加カラムを共有Postgres（dev/prod）に適用済みであること。未適用だと本APIは 500/未定義カラムになる。
2. **バナーの粒度**: 現状「ブランド共通(app_type)」。店舗別バナーが要件なら `app_banner` に `club_code` を足す設計変更が必要（member 側の `GET /member/banners` も要修正）。
3. **バナー編集の権限**: 店舗担当者に開放するか、ブランド管理者(admin)限定か。雛形は admin 限定。
4. **置換方式**: 保存は「全置換（delete→insert）」。既存 id を維持したい編集履歴要件があれば upsert 方式に変更。
5. **`query()` の実行経路**: `DB_PROXY_FUNCTION_NAME` 設定時は Lambda 経由（単一ステートメント）。本雇形は置換を **単一 CTE ステートメント**にしてあり、この経路でも動く。

## 6. 動作確認の目安
1. 型: `npx tsc --noEmit`（本雛形はエラーなしを確認済み）。
2. 景品: admin で `POST /api/store-settings/stamp-card`（clubCode＋prizes）→ `GET /member/stamp-card`（対象店舗の会員JWT・最新カード）に `prizes` が出る。
3. バナー: admin で `POST /api/store-settings/banners`（appType）→ `GET /member/banners`（該当 app_type のJWT）に反映。アプリのホーム（お知らせ下）に表示。
